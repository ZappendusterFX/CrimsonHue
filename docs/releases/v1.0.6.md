# CrimsonHue 1.0.6 — OpenRGB alongside Hue

Bring Crimson Desert's engine-light telemetry to compatible OpenRGB devices
alongside Philips Hue Entertainment, with all setup in the existing in-game mixer.
Use **CrimsonDesertTelemetry 2.2.8** for the current game and shared OpenRGB panel.

- Adds an optional OpenRGB backend controlled by the common Start/Stop action.
- Adds a separate OpenRGB tab with SDK device discovery, device selection and
  individual positions in a rotatable 3D room. Drag to move across the room and
  adjust Height for vertical placement.
- Saves device selections and positions by stable hardware identity, including
  disconnected devices, independently of Hue areas and shared mixer presets.
- Adds independent OpenRGB Light coverage and Background light controls, starting
  at 90° and 25% of the common background amount, plus a 25% default output limit.
  These defaults give desk devices broader local-effect coverage with less neutral
  fill; source RGB and Hue's own room mapping stay unchanged.
- Supports OpenRGB SDK 4/5/6, including opaque device IDs in SDK 6. Uses eligible RGB
  zones, skips keyboard matrix holes, limits gamepads to their Lightbar and does
  not resize empty headers.
- Retains output freshness checks, bounded SDK operations and restoration of prior
  modes/colors while ownership and connectivity permit. An OpenRGB failure leaves
  a healthy Hue stream running. Demo and synthetic previews never drive hardware.
- Includes the existing movement smoothing and swinging-lantern handling from 1.0.4.

OpenRGB is disabled by default for new users. Start its local SDK server on port
6742, enable OpenRGB in the mixer, read/select devices and place them around your
seat. Exit other software controlling the same devices. The existing Hue bridge
and Entertainment area are still required; standalone OpenRGB without Hue setup
is not part of this release. Each selected device uses one virtual room position,
not independent positions for its keys or LEDs.

CDT 2.2.8 owns game compatibility and conditional address recovery. It waits for
valid game-world data and shows progress when an update requires a search.
Changed engine layouts can still require a CDT update. CrimsonHue continues to
consume only the neutral telemetry API and does not gate output on game-build labels.

Validation includes 161 Core tests, the exact packaged hidden-controller smoke and
folder/ZIP checks. Shared-renderer tests and preserved-recording replays cover the
same OpenRGB implementation. The owner confirmed hardware color identification
and the first parallel in-game trial; the latest color policy has replay evidence
without a separate optical measurement. The exact public ZIP is not a new installed
game/physical-output test. See [OpenRGB evidence](../OPENRGB.md).

Close the game and install **CrimsonHue-1.0.6-asi-win-x64.zip** through your mod
manager, together with CDT 2.2.8. **.NET 8 Desktop Runtime x64** remains required
separately. Saved pairing, settings and room placements are preserved.
See the [setup guide](../USER-GUIDE.md#openrgb-alongside-hue).

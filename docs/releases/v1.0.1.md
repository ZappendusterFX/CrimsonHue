# CrimsonHue 1.0.1

Fixes the **Own lantern** control being bypassed after a game update even when
CDT supplies the same complete lantern pair. CrimsonHue now evaluates the light
metadata instead of requiring the old Steam build25477059.

CrimsonHue still consumes only CDT's neutral API. CDT owns game-build validation;
Hue keeps schema, paired-capture, visibility and freshness validation. The
lantern's existing checks are retained: all-around feed, player-root forward,
two unique standalone spotlights, matching cone angles/directions, body-relative
positions, coincident origins and the2.5 RGB ratio. No source index, world position
or build number alone identifies the lantern. CDT does not provide an ownership
ID; this remains a conservative heuristic. Changed/incomplete/ambiguous pairs
keep ordinary spotlight strength. Raw telemetry and settings are unchanged.

Use CDT2.2.6 for Crimson Desert patch2.04.05. The existing API schema1.6 and Hue
panel contract are unchanged. There is no game-memory reader or telemetry hook
in CrimsonHue, and no new CDT field or schema is introduced.

Verification and package evidence are recorded in
[lantern compatibility](../LANTERN-CDT-COMPATIBILITY.md). Synthetic/replay evidence
is separate from actual new-build lantern recognition and physical lamp output.
Installation remains exclusively the owner's responsibility.

# CrimsonHue 1.0.0

CrimsonHue now runs inside Crimson Desert as a single ASI, with its mixer hosted
by **CrimsonDesertTelemetry 2.2.5** in the shared in-game renderer. The lamp
controller installs no graphics hooks and opens no separate window or process.
This replaces the public 0.3.3 desktop EXE distribution.

## What changed

- Lighting offers Recommended/Custom modes with overall brightness, local
  effects, background light and coordinated response timing. Custom tuning is
  preserved separately.
- Point lights (0–200%), Spotlights (0–1000%) and Own lantern (0–100%) have
  independent weights. Recommended uses 100% / 100% / 10%. Lantern recognition
  is conservative and build-specific; unmatched sources retain ordinary weight.
- Continuous spherical mapping and temporal smoothing replace hard axis cuts.
  Recommended/reset uses a 30° source radius, 20% edge softness and focus 4.
- Optional per-light/per-segment wall regions support vertical or horizontal
  washers, mixed ordinary lights and an explicit bounded channel test.
- Bridge setup is guided, existing Hue identities are preserved, and layout
  checks include service placement as well as channel geometry.
- X, Hide settings and Ctrl+Shift+H hide the mixer while lighting continues.
  CDT includes held-input handoff and duplicate-cursor corrections.
- Advanced keeps 31 numeric controls, raw input/readouts and selective version-2
  preset import/export. Version-1 presets remain readable with neutral weights.

## Install or upgrade

Close the game and stop any old desktop CrimsonHue sync. Install
`CrimsonHue-1.0.0-asi-win-x64.zip` together with
[CDT 2.2.5](https://github.com/ZappendusterFX/CrimsonDesertTelemetry/releases/tag/v2.2.5)
through DMM or the documented manual ASI-loader route. Install Microsoft
**.NET 8 Desktop Runtime x64** for CrimsonHue and CDT's documented
**.NET 8 ASP.NET Core Runtime x64** prerequisite separately. Neither runtime,
CDT nor an ASI loader is included in the Hue ZIP.

The Hue ZIP contains one ASI and guides/notices, with embedded application files.
Existing current-user settings/pairing remain local. Start physical output
explicitly; demo never sends lamp output. **Stop and wait for stopped status
before quitting the game.**

[Complete setup and tuning guide](https://github.com/ZappendusterFX/CrimsonHue/blob/v1.0.0/docs/USER-GUIDE.md)

## Known limits and evidence

Physics rays measure collision, not optical visibility. Visible lamps behind
glass or inside enclosing collision shells can be excluded before weighting;
more Point/Spot strength cannot restore them. Renderer-derived optical
visibility is not implemented. The output is an engine-data lighting estimate,
not screen sampling, photometry, complete illumination or simulated spotlight
cones/reflections.

Own-lantern matching uses the observed complete pair on game build 25477059,
without an engine ownership ID. Unsupported or ambiguous input remains ordinary
spotlight input. Ambient is a relative sky/openness layer, not all indoor light.

The owner has used private builds in-game with physical lamps. Automated
controller/transport/GPU verification and read-only live-input evidence are
recorded separately; they do not establish exact public-ZIP installation,
game/input, HDR-display, every mod manager or other-hardware acceptance. The
release process does not install files into the running game or send lamp output.
Process exit or an unreachable bridge can prevent cleanup/restoration.

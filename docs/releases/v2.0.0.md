# CrimsonHue 2.0.0 — Hue, OpenRGB and Tuya LAN

Choose any combination of **Philips Hue Entertainment**, **OpenRGB** and **Tuya LAN** in **Setup → Lighting outputs**. OpenRGB and Tuya can each run without a Hue bridge. Existing Hue pairing and saved OpenRGB placements are preserved.

- Use OpenRGB's local SDK server to read devices, select them and place them in the room.
- Add compatible **Tuya Wi-Fi 3.5 RGB lamps** in the Tuya LAN tab with their local host, device ID and key. Keys are protected by Windows for your account. Place each lamp in the room and set its output limit. **Check connection** tests TCP reachability.
- **Start lighting sync** runs configured selected outputs independently. A failed output leaves healthy outputs running. **Stop** waits for bounded cleanup. Tuya attempts to restore a supported previous state when it can still confirm ownership.
- Menu lighting, shared tuning and demo preview remain available. Demo sends no physical output. The controller-specific Skills-menu issue remains open.

Install the **CrimsonHue-2.0.0-asi-win-x64.zip** asset with the game closed, alongside [Crimson Desert Telemetry 2.2.10](https://github.com/ZappendusterFX/CrimsonDesertTelemetry/releases/tag/v2.2.10). CrimsonHue requires **.NET 8 Desktop Runtime x64**. CDT requires **.NET 8 ASP.NET Core Runtime x64**. Both use the game's x64 ASI loader.

Tuya support is limited to compatible Wi-Fi protocol 3.5 RGB devices. Hardware response and restoration vary by device. See the [setup guide](https://github.com/ZappendusterFX/CrimsonHue/blob/v2.0.0/docs/USER-GUIDE.md) and [validation record](https://github.com/ZappendusterFX/CrimsonHue/blob/v2.0.0/docs/releases/v2.0.0-validation.md).

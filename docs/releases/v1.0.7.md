# CrimsonHue 1.0.7 — configurable menu lighting and OpenRGB reset

Keep a steady room color during game menus and edit it directly in the in-game
HUD. Use **CrimsonDesertTelemetry 2.2.9** for the independent simulation-pause
signal, suspended acquisition and matching shared controls.

- Adds **Lighting → Menu lighting** with color picker, hex input, brightness,
  Save and Reset. Warm white at 20% remains the default. The optional **Gold
  preset** selects 80% and RGB 1/0.65/0.08; existing settings are preserved.
- Holds the configured color only while CDT supplies fresh confirmation that
  simulation and acquisition are paused. Overall brightness, channel balance and
  the OpenRGB output limit still apply. Output connections remain open, and
  ordinary Stop/ownership/restoration behavior is retained.
- Discards pre-pause local and ambient data, waits briefly for fresh gameplay
  input and blends back over 500 ms after resume. Missing, stale or disconnected
  activity data uses the existing stale-input safety behavior. Older CDT endpoints
  retain ordinary lighting without automatic menu mode. Demo never drives hardware.
- Adds **Reset OpenRGB settings** to disable OpenRGB and restore its 25% output
  limit, 90° coverage, 25% background and default device positions while preserving
  the SDK port and Hue setup. **Remove disconnected devices** removes saved absent
  entries after a successful inventory read, preserving connected-device placement.
  Both require stopped lighting. **Reset view** still changes only the viewing angle.
- Includes the existing optional OpenRGB output, spatial device placement,
  movement smoothing and own-lantern handling from earlier releases.

Menu lighting is **not a fix for the Skills-menu stutter or repeated controller
hover sounds**. Those persisted in the owner's menu-mode test. Pause detection
observes stopped simulation progress after approximately 500 ms; it does not
recognize individual menu screens. CDT 2.2.9 also avoids treating intentional
capture pauses as light failures or announcing readiness on every menu resume.

CrimsonHue consumes CDT's neutral API. Game compatibility and build validation
remain CDT's responsibility; CrimsonHue does not gate lighting on game-build labels.

Close the game and install **CrimsonHue-1.0.7-asi-win-x64.zip** together with
**CDT 2.2.9**. **.NET 8 Desktop Runtime x64**, a Hue bridge and an existing Hue
Entertainment area remain required. OpenRGB is optional and disabled by default
for new users. Saved pairing, room placement and mixer settings are preserved.

Synthetic tests and package/controller checks are separate from game and hardware
acceptance. The owner tested menu lighting in the preceding private builds; the
exact public ZIP is not an additional installed-game or optical-output test.
See the [setup and tuning guide](https://github.com/ZappendusterFX/CrimsonHue/blob/v1.0.7/docs/USER-GUIDE.md)
and [OpenRGB evidence](https://github.com/ZappendusterFX/CrimsonHue/blob/v1.0.7/docs/OPENRGB.md).
